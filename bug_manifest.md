## Correctness

### C2. Non-finite switch labels produce invalid engine JSON (high)

- **Where**: `sonolus/backend/_opt/emit.pyx:226-230` (`_leaf_cond`), `sonolus/build/engine.py:344` (`package_data`).
- **What**: `_emit_numeric` exists to keep non-finite values out of emitted leaves by lowering them to EngineRom
  reads, but `_leaf_cond` is a second, unguarded entry point to `_float_leaf`, so a non-finite switch case label is
  serialized as bare `Infinity`/`-Infinity`/`NaN`. `json.dumps` defaults to `allow_nan=True`, so packaging emits it
  without complaint and the whole packaged engine payload is invalid JSON (strict parsers, including
  spec-conformant servers, reject it). A one-arm comparison against `math.inf` already ships correctly via ROM,
  which confirms the label path is the anomaly. User-level trigger: an `if`/`elif` chain or `match` against
  `math.inf`/`1e999` constants that lowers to a switch.
- **Repro**: `repro/nonfinite-json/repro_a_user_program.py` (end-to-end across 2 modes x 3 levels x 3 values).
- **Fix sketch**: route non-finite conds in `_leaf_cond` through the same ROM lowering (`self._rom_read(...)`).
  Case labels may legally be computed nodes (`interpret.py:416` runs each case), so the lowering is valid there.
  Separately (T8), pass `allow_nan=False` in `package_data` as a packaging-time backstop.

### C3. zip/map over-advance effectful arms (medium)

- **Where**: `sonolus/script/iterator.py:96-101` (`_Zipper.next`); `sonolus/script/internal/builtin_impls.py:529-532`
  (multi-iterable `map` builds on `zip`).
- **What**: `_Zipper.next` advances every arm and only then scans for `Nothing`; CPython pulls left to right and
  stops at the first exhausted arm. On the terminating round each arm to the right of the first exhausted one
  receives a `next()` CPython never issues: map/filter callbacks run extra times (a filter arm can burn several
  source elements in that one call), a generator body executes past its last yield, and a user `SonolusIterator`
  whose `next()` writes memory performs an extra write. This diverges in returned values, not just logs: the
  repro's case E returns 4 in Python and 5 compiled, failing `run_and_validate`'s value assert
  (`tests/script/conftest.py:206`). Reaches tuple/generator arms too via `map()`/`filter()`; no Array required.
- **Repro**: `repro/zip-over-advance/repro.py` (6 cases, self-checking) and `repro_generator.py`.
- **Fix sketch**: make `_Zipper.next` short-circuit left to right over its right-nested `Pair` chain
  (`iterator.py:68-82`): advance `first`, return `Nothing` early, only then recurse. Earlier arms' values must stay
  live across later `next()` calls and both paths must merge out of the runtime branches; expect a
  `baseline_metrics.json` re-baseline (delete and rerun, never hand-edit). The compile-time branch
  (`builtin_impls.py:243`, direct tuple/set/dict arms) already matches CPython and must not regress; pydori's only
  zip site has effect-free bounds-checked arms, so goldens should not move.
- **Validation notes**: not one of the two pinned iterator divergences (`tests/script/test_generator.py:850-871`,
  `:907-921` are different behaviors); nothing pins this one. A maintainer could instead pin it as a third accepted
  divergence; as the code stands, the repo's own oracle rejects it.

### C4. const_eval folds trap on domain errors (medium)

- **Where**: `sonolus/script/internal/native.py:78-79`.
- **What**: when every argument is compile-time, the fold calls the Python reference body unguarded, so a
  `ValueError`/`OverflowError` (for example `math.log(-1.0)`, `math.acos(1.0000000000000002)`) becomes a
  CompilationError. Because the tracer visits both sides of every runtime branch, a domain error on a constant that
  only occurs on an unreachable path aborts a working program: the same principle that got the compile-time
  zero-step `range()` rejection reverted, and the opposite of the backend fold contract ("domain errors do not
  fold", `kernels.pyx` returns `FOLD_NOT_CONSTANT`). The `acos` case shows a live-path failure with no branch at
  all, where the runtime would produce NaN.
- **Repro**: `repro/const-eval-domain/repro_const_eval_domain.py`.
- **Fix sketch**: wrap only the fold in `try/except (ValueError, OverflowError)` and fall through to
  `native_call(op, *full_args)`, mirroring `Num.__pow__` (`num.py:427-439`). The outside-context path at
  `native.py:87` must keep raising, since there is no runtime op to fall back to there.

### C6. Failed dev rebuild corrupts decode mappings (medium)

- **Where**: `sonolus/build/dev_server.py:133-134, 148-152`; `sonolus/script/internal/context.py:452`.
- **What**: `RebuildCommand.execute` commits `project_state`/`project` to shared state before the build that may
  fail, and the failure handler does not roll back. Debug messages are numbered by first-touch order, so the
  surviving partial mapping does not merely lose codes: `decode` can print a confidently wrong message for the
  build the client is still running. Any exception path (not just CompilationError) triggers it, since
  `run_server`'s catch-all continues the REPL.
- **Repro**: `repro/dev-server/lead44_decode_after_failed_rebuild.py`.
- **Fix sketch**: build into locals and commit only after `build_project_to_existing_collection` and
  `write_collection` succeed, the discipline already applied to `last_build_time` (`:149`) and the import-failure
  path (`:121-123`), which shows the intent.

### C8. Decorated def evaluation order (low)

- **Where**: `sonolus/script/internal/visitor.py:652-674`.
- **What**: for a nested decorated `def`, defaults are visited before decorator expressions, and decorator
  expressions bottom-up. CPython (verified on 3.12/3.13/3.14 with disassembly) evaluates decorator expressions
  top-down first, then defaults, then applies bottom-up. Application order is already correct; only side-effecting
  decorator/default expressions observe the difference, silently.
- **Repro**: `repro/def-eval-order/` plus a no-sonolus CPython baseline script.
- **Fix sketch**: visit `node.decorator_list` forward into a list, then build the signature, then define, then
  apply the collected values in reverse.

### C10. Integral folds overflow into CompilationError (low)

- **Where**: `sonolus/script/num.py:53-59, 118-124, 332, 347, 362`.
- **What**: integral floats widen to exact ints for folding, and the result narrows with a bare `float(...)`.
  On overflow (intermediates around 1e300 from chained multiplies of large literals) `__add__`/`__sub__`/`__mul__`
  raise `CompilationError: int too large to convert to float` where CPython and the runtime both give inf, and a
  dead branch aborts the compile the same way. `__pow__` already guards exactly this.
- **Repro**: `repro/num-folding/`.
- **Fix sketch**: mirror `__pow__`: catch `OverflowError` and fall through to the runtime op. Note the trigger's
  intermediates are far outside the documented f32-supported range, which bounds severity, but a compile abort on a
  dead branch is still wrong under the reverted-raise principle.

### C12. package_rom crashes on out-of-f32-range constants (low)

- **Where**: `sonolus/build/engine.py:338`.
- **What**: `struct.pack("<f", value)` rejects out-of-f32-range operands (`OverflowError` for floats,
  `struct.error` for ints) instead of the saturating f64-to-f32 conversion. A `1e39` literal that reaches the ROM
  pool aborts the build with a bare traceback after all four modes have been traced and packaged, on an engine
  `sonolus check` reports as valid. The packager is the converter here: the runtime reads raw f32 bytes.
- **Repro**: `repro/package-rom-overflow/repro.py`.
- **Agreed fix direction (maintainer, 2026-08-09; not yet implemented)**: catch at ROM-add time instead of
  saturating at packaging. `ReadOnlyMemory.__getitem__` (`context.py:549-557`) is the single add site; the pool
  ships wholesale (dead-branch registrations included), so an add-time raise rejects exactly the programs that
  crash at `struct.pack` today: behavior-preserving, with a source location. Design verified during scoping:
  raise `ValueError` when a value's magnitude exceeds f32 max AND a `struct.pack("<f", v)` probe fails (the probe
  keeps the predicate exactly the packaging predicate, so values just above f32 max that round down still build);
  the `ValueError` passes through `array.py:275-277`'s TypeError-only catch and the visitor attaches the source
  location; the seeded nan/inf slots and the mro-id int arrays are unaffected (non-finite packs fine); message
  "out of range for engine data" collides with no existing message. Not `assert_true`: there is no runtime-check
  alternative, since the entry ships in packaged data regardless of reachability. A regression test belongs in
  `tests/script/test_array.py`: `run_and_validate` inside `pytest.raises(CompilationError, match="out of range
  for engine data")` on a constant Array containing `1e39` indexed by a loop-accumulated runtime index.

### C18. Final Record fields break Array containment (low)

## Performance

### P1. Unbounded runtime-constant duplication is exponential (medium)

- **Where**: `sonolus/backend/_opt/lower.pyx:654-658, 1097-1100, 1195-1217`.
- **What**: a runtime-constant tree is re-emitted at every use site ("FOLD/DUP regardless of size"), skipping the
  multi-use tree-cost gate that materializes the non-rtc case. A compounding multi-use chain over a runtime
  constant (repeated squaring; chained `Transform2d` rotations by a runtime-constant angle, an ordinary engine
  idiom that helper inlining composes) grows the lowered arena 4x per two steps: 2^N IR nodes for a linear source.
  Measured: 163,842 arena nodes at N=16 for a 24-node artifact; about 1 s at 18 chained rotate calls; tens of
  seconds low-20s. Realistic chains (<= 12 steps) cost <= 16 ms, hence medium.
- **Repro**: `repro/node-hash/source_reach.py`, `compiler_reach.py`.
- **Fix sketch**: give rtc duplication a cumulative size budget using the existing memoised `_tree_cost` machinery
  (`lower.pyx:905-939`), falling back to materialization past it. Constraints: the runtime cost model deliberately
  prefers duplication (a temp defeats the runtime's own folding), so the budget must be generous; the pinned
  flat-duplication test (`tests/backend/test_lower.py:179`) and the metrics gate constrain the change.
- **Validation notes**: upheld against the settled duplicate-regardless-of-size adjudication: that decision covers
  the runtime cost model, not unbounded compile time/memory, and `_MAX_FOLD_DEPTH` shows compile-side costs were
  meant to be bounded (the depth cap exists; the missing bound is width/total size). Loop unrolling is not a route
  (for-range is a runtime loop); written-out or helper-inlined chains are.

### P3. GetShifted rewrite grows the metric it promises not to (low)

- **Repro**: `repro/cfg-cleanup-matrix/`.

### P5. Test helpers re-trace per optimization level (low)

- **Where**: `tests/script/conftest.py` (`run_and_validate`, `run_compiled`).
- **What**: the traced CFG depends only on (callback, runtime_checks), but `compile_fn` sits inside the level loop,
  so every level pays a redundant frontend trace. Hoisting halves trace count: 7-38% off serial single-file wall
  time, about 22-30% off `pytest tests/script -n 32`, not measurable on the full `pytest -n 32` gate.
- **Repro**: `repro/test-retrace/`.

  `random.setstate(initial_random_state)` semantics must be preserved exactly (traces consume random state), and

## Method

- Phase 1: 8 lead finders (one per dimension: frontend, API types, optimizer, backend/runtime, coverage, docs,
  performance, build/CLI), 48 leads.
- Phase 2: triage against settled decisions (2 dropped, duplicates merged), then 25 investigators over 44 leads:
  45 confirmed (7 newly discovered during investigation), 6 refuted, 3 likely-settled.
- Phase 3: 22 adversarial validators over the 45 confirmed: 38 upheld, 5 downgraded, 2 overturned.
- Implementation: 9 parallel Python implementers, 5 serialized Cython implementers, a solo harness change, a
  three-lens review with fixer, and an independently verified full gate.
- Round 2: 8 finders (4 regression, 4 fresh), 35 leads, 14 investigator groups, adversarial validation per group.
- All hunt-phase agent work was read-only on the repository.
